# Локализация: руководство для переводчиков

Смежный документ для технической команды:
[руководство для разработчиков](LOCALIZATION_DEVELOPERS.md).

## 1. Где выполняется работа

Все переводы редактируются в Google Sheet. Таблица является основным источником
текстов приложения.

Переводчикам не нужно:

- редактировать ARB или Dart-файлы;
- запускать Flutter;
- работать с GitHub secrets;
- устанавливать Sheety или Shorebird;
- менять generated-код.

После подготовки переводов ответственный разработчик запускает автоматическую
проверку и публикацию.

## 2. Структура таблицы

Рабочая вкладка называется:

```text
localization
```

Первая строка:

```text
label | description | meta | ru | kk | en
```

Назначение колонок:

| Колонка | Что находится внутри | Можно ли менять переводчику |
|---|---|---|
| `label` | Технический ключ текста | Нет |
| `description` | Контекст использования | Можно предложить уточнение |
| `meta` | Технические параметры строки | Нет, без согласования |
| `ru` | Русский перевод | Да |
| `kk` | Казахский перевод | Да |
| `en` | Английский перевод | Да |

Пример:

| label | description | meta | ru | kk | en |
|---|---|---|---|---|---|
| `profileTitle` | Заголовок экрана профиля | `{}` | Профиль | Профиль | Profile |

## 3. Что нельзя менять самостоятельно

Без согласования с разработчиком нельзя:

- переименовывать `label`;
- удалять строку целиком;
- менять название вкладки `localization`;
- менять заголовки первой строки;
- добавлять или удалять locale-колонки;
- редактировать JSON в `meta`;
- менять имена placeholders;
- изменять структуру plural-выражения;
- объединять ячейки в рабочем диапазоне.

Переименование `label` ломает связь с кодом. Удаление строки удалит текст из
generated API при следующей публикации.

## 4. Обычное изменение перевода

1. Найдите строку по `label` или `description`.
2. Убедитесь, что строка относится к нужному экрану и контексту.
3. Измените только ячейку своей локали.
4. Сохраните placeholders без изменений.
5. Не оставляйте ячейку пустой.
6. Проверьте орфографию, пунктуацию и смысл.
7. Сообщите ответственному, какие строки готовы к публикации.

Google Sheets сохраняет изменения автоматически, но приложение не обновляется
сразу. Разработчик должен запустить workflow публикации.

## 5. Добавление нового текста

Обычно новую строку создаёт разработчик, потому что новый `label` должен
соответствовать коду приложения.

Разработчик заполняет:

```text
label
description
meta
базовый текст
```

Переводчик:

1. Проверяет `description`.
2. Заполняет назначенную locale-колонку.
3. Сохраняет placeholders.
4. Проверяет plural-формы, если они есть.
5. Помечает строку готовой согласованным способом команды.

Если контекста недостаточно, не угадывайте. Запросите:

- экран или сценарий;
- скриншот;
- ограничение по длине;
- обращение на «ты» или «вы»;
- род, число и роль пользователя;
- значение placeholder.

## 6. Placeholders

Placeholder — техническая вставка, которую приложение заменяет реальным
значением.

Пример:

```text
Добро пожаловать, {userName}!
Welcome, {userName}!
Қош келдіңіз, {userName}!
```

Можно менять положение placeholder в предложении, но нельзя менять его имя:

```text
Правильно:   Добро пожаловать, {userName}!
Неправильно: Добро пожаловать, {username}!
Неправильно: Добро пожаловать!
Неправильно: Добро пожаловать, {имя}!
```

Сравнение чувствительно к написанию:

```text
{userName} != {username} != {UserName}
```

Если в исходном тексте два placeholders, оба должны остаться:

```text
{userName} добавил {itemCount} товаров
```

## 7. Plural-формы

Plural используется, когда текст зависит от количества.

### Русский

Русский текст обычно содержит:

```text
one
few
many
other
```

Пример:

```text
{count, plural,
  one{{count} товар}
  few{{count} товара}
  many{{count} товаров}
  other{{count} товаров}
}
```

### Английский

Английский текст содержит:

```text
one
other
```

Пример:

```text
{count, plural,
  one{{count} item}
  other{{count} items}
}
```

### Казахский

В текущей автоматической проверке для казахского обязательна категория:

```text
other
```

Имя счётчика должно быть одинаковым во всех языках:

```text
Правильно:   {count, plural, ...}
Неправильно: {cnt, plural, ...}
```

Меняйте слова внутри веток, но не удаляйте внешние фигурные скобки, запятые,
названия категорий или имя счётчика. Если требуется изменить структуру, привлеките
разработчика.

## 8. Колонка `description`

Хорошее описание отвечает на вопросы:

- где показан текст;
- что делает пользователь;
- является ли это кнопкой, заголовком или ошибкой;
- есть ли ограничение по длине;
- что означает placeholder.

Хороший пример:

```text
Заголовок кнопки подтверждения удаления профиля
```

Плохой пример:

```text
Кнопка
```

Если перевод может иметь разные варианты в разных контекстах, попросите
разработчика уточнить `description` или создать отдельный ключ.

## 9. Колонка `meta`

Для простой строки обычно используется:

```json
{}
```

`meta` может содержать технические сведения о placeholders, типах и формате.
Переводчик не должен исправлять `meta` вручную без разработчика, даже если JSON
кажется понятным.

Некорректный JSON остановит генерацию.

## 10. Правила качества перевода

- Сохраняйте смысл, а не буквальную структуру исходного языка.
- Используйте утверждённую терминологию продукта.
- Соблюдайте единый стиль обращения.
- Проверяйте текст вместе с `description`.
- Не добавляйте HTML-теги.
- Не вставляйте переносы строк без необходимости.
- Не оставляйте пробелы в начале и конце.
- Не заменяйте обычные пробелы нестандартными символами.
- Учитывайте длину кнопок, вкладок и заголовков.
- Не используйте машинный перевод без проверки человеком.

Запрещённые технической проверкой теги включают:

```text
script
iframe
img
a
div
span
style
```

## 11. Как текст проходит проверку

После завершения перевода разработчик запускает:

```text
Google Sheet
-> генерация ARB и Dart
-> проверка ключей
-> проверка placeholders
-> проверка plural
-> Flutter analyze
-> Flutter tests
-> ручная проверка diff
-> staging patch
```

Публикация обычно остановится или потребует исправления, если:

- ключ отсутствует в одной из локалей;
- placeholder переименован или удалён;
- plural-форма отсутствует;
- JSON или ICU-синтаксис повреждён;
- generated Dart не компилируется;
- Flutter tests не проходят.

Пустая locale-ячейка особенно опасна: генератор может пропустить всю строку.
Поэтому ответственный дополнительно проверяет заполненность Sheet и generated
diff перед публикацией.

## 12. Что означает статус публикации

### Подготовлено в Sheet

Текст сохранён в таблице, но ещё не находится в приложении.

### Validation passed

Автоматические проверки прошли. Это ещё не означает, что patch опубликован.

### Staging

Перевод опубликован только в тестовый track и проверяется командой.

### Stable

Перевод разрешён для production-пользователей соответствующей версии приложения.

После получения patch приложение обычно применяет его при следующем запуске:

1. Первый запуск скачивает обновление.
2. Приложение полностью закрывается.
3. Второй запуск показывает новый перевод.

## 13. Как передать переводы на публикацию

Перед передачей ответственному проверьте:

- название вкладки не изменено;
- заголовки колонок не изменены;
- все назначенные строки заполнены;
- placeholders сохранены;
- plural-структура сохранена;
- `description` понятен;
- нет случайно удалённых строк;
- тексты просмотрены носителем языка или ответственным редактором.

В сообщении ответственному укажите:

```text
Локаль:
Изменённые label:
Причина изменения:
Нужна ли срочная публикация:
Кто проверил перевод:
```

Пример:

```text
Локаль: kk
Изменённые label: profileTitle, deleteProfileWarning
Причина изменения: исправлена терминология профиля
Нужна ли срочная публикация: нет
Кто проверил перевод: имя редактора
```

## 14. Исправление ошибки после публикации

Если обнаружена ошибка:

1. Не удаляйте строку.
2. Исправьте значение в нужной locale-колонке.
3. Проверьте placeholders и plural.
4. Сообщите ответственному, что нужна повторная публикация.
5. Укажите `label`, локаль и правильный текст.

Если ошибка критическая, ответственный может остановить продвижение staging patch
или изменить активный track в Shorebird.

## 15. Типовые ошибки

### Перевод исчез после генерации

Вероятно, изменение было сделано только в ARB, а не в Google Sheet. Source of
truth — Sheet. Добавьте или восстановите строку в таблице.

### Публикация сообщает о placeholder

Сравните имена во всех языках. Они должны совпадать символ в символ.

### Публикация сообщает о plural

Проверьте обязательные категории и парность фигурных скобок. Не исправляйте
структуру наугад — подключите разработчика.

### Изменение есть в Sheet, но не видно в приложении

Возможные причины:

- publish workflow ещё не запускался;
- validation или tests упали;
- patch ожидает approval;
- patch находится только в `staging`;
- приложение ещё не перезапущено после загрузки patch;
- установленная версия приложения отличается от версии Shorebird release.

### Нельзя редактировать таблицу

Запросите доступ Editor у владельца Google Sheet. Не используйте credentials
service account на личном компьютере переводчика.
